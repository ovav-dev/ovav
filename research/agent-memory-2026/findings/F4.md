# F4: Fast LLM-Readable Memory Formats — OVAV MEMORY Recommendation

> Research for OVAV MEMORY: "lightweight and fast for AI model reading"
> 2026-08-06 · 30+ sources across 5 research angles

## Key findings

### [1] JSON with role/content is the ONLY production-standard context injection format
Every major agent framework (LangChain, CrewAI, LlamaIndex, AutoGen, Claude Code) uses JSON dicts with `{"role": "user/system/assistant", "content": "..."}` for memory-to-model injection. Binary formats (Protobuf, MessagePack) exist in AI infrastructure but never at the context-injection layer — no benchmarks show binary outperforming JSON for LLM tokenization throughput. Use JSON.
- sources: F1 (CrewAI, LangChain, LlamaIndex, AutoGen docs), F3 (binary format gap)

### [2] Memory storage and injection format are decoupled — storage is swappable
Memory lives in LanceDB, PostgreSQL, Redis, or in-memory dicts; it serializes to JSON role/content at injection time. OVAV MEMORY should decouple its on-disk format from its injection format — storage choice (SQLite, JSON files, etc.) has no impact on model read speed.
- sources: F1, F2

### [3] LLM reasoning accuracy collapses at ~3,000 tokens — far below context limits
A 24-point accuracy drop (0.92→0.68) occurs at ~3,000 tokens across all tested models (ACL 2024, peer-reviewed). Perplexity is a misleading proxy for reasoning quality. For OVAV MEMORY: keep injection payloads under 2–3 KB of *relevant* content; irrelevant context degrades performance, not just efficiency.
- sources: F5 (Levy et al. ACL 2024, arXiv:2402.14848)

### [4] "Lost-in-the-middle" is real, data-type dependent, and unsolved
Models retrieve facts from context start/end reliably but lose facts in the middle (40–60% degradation). Numbers fail middle, letters fail end. No 2025-era long-context model has solved this. Progressive disclosure — compact summary in context + full content on demand — is the mitigation used by Letta MemFS and Anthropic guidance.
- sources: F5 (Liu et al. TACL 2023, DENIAHL 2024, DeepMind 2025)

### [5] Hierarchical memory with adaptive retrieval outperforms summarization-only and full injection
Letta's sleep-time compute (background agent rewrites memory), CrewAI's composite scoring (semantic 0.5 + recency 0.3 + importance 0.2), and ReaLM-Retrieve (reasoning-step uncertainty triggers retrieval, +10.1 pp F1, 47% fewer calls) all converge on: tiered memory + selective retrieval beats comprehensive context dumps and fixed-interval summarization.
- sources: F1 (CrewAI scoring), F3 (Letta sleep-time), F5 (ReaLM-Retrieve SIGIR 2026)

### [6] Semantic caching of reasoning improves structured domains but degrades heterogeneous ones
On MATH500/AIME2024: semantic cache at k=5 → +3–10 pp. On heterogeneous science (GPQA): same cache degrades −2.4 pp at k=15. OVAV MEMORY should use domain classification to select caching aggressiveness — structured/code domains can cache more aggressively than mixed-conversation memory.
- sources: F5 (Tekin et al. Dec 2025, arXiv:2601.08846)

### [7] Progressive disclosure (summary always-in-context + on-demand detail) is universal pattern
Both Anthropic's guidance and Letta's production MemFS use: compact summary (1–3 KB) always in context + full memory/documents loaded only when task requires them. Claude Code loads only first 200 lines / 25KB of MEMORY.md at session start. OVAV MEMORY should follow: store full detail, inject summary, fetch more on demand.
- sources: F2 (Anthropic compaction), F3 (Letta MemFS, Context Constitution), F4 (Claude Code)

## OVAV MEMORY format recommendation

| Layer | Format | Rationale |
|---|---|---|
| Injection to model | JSON `{"role": "user/assistant/system", "content": "..."}` | Universal standard, all frameworks use this |
| Storage | Swappable (file-based JSON or SQLite) | Decoupled from injection; no model impact |
| Memory organization | Hierarchical scopes with importance-weighted recall | CrewAI/Letta proven pattern |
| Always-in-context | Compact summary ≤2 KB | Avoids accuracy cliff at 3K tokens |
| On-demand retrieval | Hybrid sparse+dense vector search + reranker | 12–18% NDCG@10 over dense-only; 61%→84% top-1 accuracy |
| Retrieval trigger | Reasoning-step uncertainty, not token count | +10.1 pp F1, 47% fewer calls (ReaLM-Retrieve) |
| What to avoid | Binary formats for injection; comprehensive dumps; irrelevant content | No benchmark support; context pollution is proven harmful |
