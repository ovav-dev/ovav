# F5: Synthesis — Rolling Memory and Importance Weighting in Agent Systems (2024–2026)

## Key Conclusions

### Rolling Context Windows
The dominant production pattern is **composite scoring** (semantic similarity + recency decay + LLM-inferred importance) with tunable weights. CrewAI's implementation is the most detailed: default `recency=0.3, semantic=0.5, importance=0.2`, 30-day half-life, two-tier dedup (0.98 intra-batch no-LLM, 0.85 consolidation LLM-driven). LangChain uses three middleware strategies (trim/delete/summarize) with token-count triggers. All frameworks require explicit memory invocation — no passive continuous injection.

### Importance Scoring
The 2024–2026 consensus is **LLM-inferred importance at save time** — not user-tagged. No major framework uses manual importance scores. Importance is one axis of a three-axis composite (alongside recency and semantic similarity), making it tunable without being manually curated.

### Forgetting Curves
**No production system uses time-decay forgetting curves.** The actual pattern is LLM-driven eviction: MemGPT/Letta let the model judge what to forget. The critical unsolved problem is **memory rot** — memories become generic after repeated refinement cycles. AgentMemBench (Aug 2026) proves all current approaches (recency windows, summaries, entity graphs) fail at long horizons (Recall@5 ≤ 0.005). The production workaround is **sleep-time compute** (dedicated background agent rewriting primary memory during idle periods).

### RAM vs Flat Memory
The ~5-session threshold is the critical divider: within 5 sessions, flat context performs comparably to vector RAG; beyond that, dense retrieval dominates (Recall@5 0.573 vs ≤0.005) at 17x token cost. **Reconstructive retrieval** (adapting memories to context) outperforms verbatim replay — a key architectural implication. The emerging consensus is a **three-layer hierarchy** (episodic → semantic wiki → procedural routing), appearing independently in TrajWiki, ChronoMem, and UniMem (2026).

### Production Memory Systems
Letta's Context Repositories (MemFS — git-backed Markdown files with YAML frontmatter, February 2026) and the sleep-time compute pattern represent the most advanced production memory architecture. MCP has no native memory concept — memory must be implemented as an explicit Resource poll. Memory is opt-in across all frameworks; no passive continuous injection exists. Microsoft Foundry provides a managed platform-level memory tool (preview, May 2026).

### Memory Bank Pattern
No standardized "Memory Bank" protocol exists — the term is community shorthand. The actual convergent pattern is: **hierarchical scope tree + progressive disclosure + token-space continual learning** (context persists independently of model weights, making memories portable across model generations). Letta's Context Constitution (CC0, April 2026) formalizes this as "context = identity = memory."

## For OVAV MEMORY Subsystem Design

1. **Start with composite scoring** (CrewAI pattern) — semantic + recency + importance as the retrieval ranking foundation
2. **Implement LLM-inferred importance at write time** — avoid manual tagging; let the LLM judge importance when saving
3. **Two-tier dedup** — intra-batch at 0.98 cosine (cheap, no LLM) + consolidation at 0.85 (LLM-driven)
4. **Adopt progressive disclosure** — keep summaries in context, load full memories on demand
5. **Consider git-backed storage** (MemFS pattern) — enables versioning, concurrent subagent processing, and easy inspection
6. **Do NOT implement time-decay forgetting** — the evidence shows LLM-driven eviction is the production standard
7. **Watch for memory rot** — repeated refinement degrades memory quality; consider a periodic full-reset or re-ingestion strategy
8. **The ~5 session threshold** — below it, flat context is sufficient; above it, invest in vector retrieval
