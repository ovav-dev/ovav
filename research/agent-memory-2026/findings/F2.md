# F2: Agent frameworks memory implementations

## Findings

### [1] CrewAI uses a unified Memory class with LanceDB as the default storage backend and composite retrieval scoring
- quote: "Default: LanceDB, stored under `./.crewai/memory`" and "Recall results are ranked by a weighted combination of three signals: semantic_weight * similarity + recency_weight * decay + importance_weight * importance"
- url: https://docs.crewai.com/concepts/memory
- source_type: primary
- published: unknown (docs, no date visible)
- confidence: high

### [2] CrewAI Memory uses hierarchical scopes (filesystem-like paths) with LLM-inferred placement and per-scope isolation
- quote: "Memories are organized into a hierarchical tree of scopes, similar to a filesystem. Each scope is a path like `/`, `/project/alpha`, or `/agent/researcher`. Scopes provide context-dependent memory -- when you recall within a scope, you only search that branch of the tree"
- url: https://docs.crewai.com/concepts/memory
- source_type: primary
- published: unknown
- confidence: high

### [3] CrewAI Memory saves are non-blocking and batched, with automatic deduplication at 0.98 cosine similarity within a batch
- quote: "`remember_many()` is non-blocking -- it submits the encoding pipeline to a background thread and returns immediately" and "When using `remember_many()`, items within the same batch are compared against each other before hitting storage. If the similarity is >= 0.98, the later one is silently dropped"
- url: https://docs.crewai.com/concepts/memory
- source_type: primary
- published: unknown
- confidence: high

### [4] LangGraph separates short-term memory (checkpointer) from long-term memory (store), with multiple production database backends for each
- quote: "Short-term memory (thread-level persistence) enables agents to track multi-turn conversations" using checkpointer; "Use long-term memory to store user-specific or application-specific data across conversations" using store; both support Postgres, MongoDB, Redis, Oracle backends
- url: https://docs.langchain.com/oss/python/langgraph/add-memory
- source_type: primary
- published: unknown
- confidence: high

### [5] LangGraph's long-term store supports semantic search via optional vector index embedding, while checkpointer persists full conversation state per thread_id
- quote: "Enable semantic search in your graph's memory store to let graph agents search for items in the store by semantic similarity" via `index={"embed": embeddings, "dims": 1536}`; checkpointer uses `thread_id` for session continuity
- url: https://docs.langchain.com/oss/python/langgraph/add-memory
- source_type: primary
- published: unknown
- confidence: high

### [6] LlamaIndex Memory class uses a token-limited FIFO buffer for short-term and three long-term memory block types (VectorMemoryBlock, FactExtractionMemoryBlock, StaticMemoryBlock)
- quote: "`token_limit` (default: 30000): The maximum number of short-term and long-term tokens to store" and "chat_history_token_ratio (default: 0.7): The ratio of tokens in the short-term chat history to the total token limit. If exceeded, oldest messages flushed into long-term memory"; long-term blocks include VectorMemoryBlock for semantic search, FactExtractionMemoryBlock for LLM fact extraction
- url: https://docs.llamaindex.ai/en/latest/module_guides/deploying/agents/memory.html
- source_type: primary
- published: unknown
- confidence: high

### [7] AutoGen (Microsoft AutoGen AgentChat) defines a Memory protocol with add/query/update_context/clear/close methods, implemented by ListMemory, ChromaDBVectorMemory, RedisMemory, and Mem0Memory
- quote: "AgentChat provides a Memory protocol that can be extended to provide this functionality. The key methods are `query`, `update_context`, `add`, `clear`, and `close`" and "Currently the following example memory stores are available: ChromaDBVectorMemory, RedisMemory, Mem0Memory"
- url: https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/memory.html
- source_type: primary
- published: unknown
- confidence: high

### [8] AutoGen ChromaDBVectorMemory uses a score_threshold (default 0.4) and top-k (default 2) for retrieval filtering with cosine similarity
- quote: "k=2: Return top k results, score_threshold=0.4: Minimum similarity score" and "distance_metric: cosine"
- url: https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/memory.html
- source_type: primary
- published: unknown
- confidence: high

### [9] All four frameworks (CrewAI, LangGraph, LlamaIndex, AutoGen) treat memory as an explicit, opt-in component passed to agents -- not automatic background ingestion
- quote (CrewAI): "Pass `memory=True` for default settings, or pass a configured `Memory` instance"; (LangGraph): "compile a graph with a store" and checkpointer; (LlamaIndex): "set the memory for an agent by passing it into the `run()` method"; (AutoGen): "pass the memory store to your agent"
- url: https://docs.crewai.com/concepts/memory; https://docs.langchain.com/oss/python/langgraph/add-memory; https://docs.llamaindex.ai/en/latest/module_guides/deploying/agents/memory.html; https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/memory.html
- source_type: primary
- published: unknown
- confidence: high

### [10] Microsoft Foundry Agent Service provides a managed "memory" tool in its toolbox as a built-in platform feature, usable by any hosted agent framework
- quote: "Toolbox lets you define a curated set of tools once, manage them centrally in Foundry, and expose them through a single MCP-compatible endpoint" and "Some tools, including memory and web search, are in preview"
- url: https://learn.microsoft.com/en-us/azure/foundry/agents/overview
- source_type: secondary
- published: 2026-05-27 (ms date)
- confidence: medium

### [11] None of the four major open-source frameworks implement passive/continuous memory injection -- all require explicit memory.put() or agent.run(memory=...) calls
- quote: All documentation across CrewAI, LangGraph, LlamaIndex, and AutoGen shows memory being explicitly passed or explicitly managed via put/add calls; none implement automatic background ingestion without explicit invocation
- url: https://docs.crewai.com/concepts/memory; https://docs.langchain.com/oss/python/langgraph/add-memory; https://docs.llamaindex.ai/en/latest/module_guides/deploying/agents/memory.html; https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/memory.html
- source_type: primary
- published: unknown
- confidence: high

## Dead ends
- "AutoGen memory" search returned only AgentChat documentation (microsoft.github.io/autogen); the specific autogen-agentchat memory module URL returned 404; the core autogen-core memory protocol details required navigating through the agentchat-user-guide which served as the primary AutoGen memory reference
- Could not locate Mem0 (the company/product) primary documentation to verify the Mem0Memory integration claims; used the AutoGen docs as the source for that integration detail
- No peer-reviewed academic sources found for any of the four frameworks' memory implementations -- all sources were framework documentation (primary) or Microsoft marketing docs (secondary)

## Suggested follow-ups
- Does Mem0 (mem0.ai) have official documentation confirming its role as a cross-framework memory backend? The AutoGen integration references it but it's unclear if it is a standalone product or a pattern
- How do CrewAI, LangGraph, LlamaIndex, and AutoGen differ in their treatment of session-only vs persistent memory -- do any frameworks automatically persist session memory without explicit save calls?
- Is there a convergence happening around storage backends? All four frameworks now support Postgres, Redis, and LanceDB/ChromaDB as memory backends -- is there a de facto standard emerging?
