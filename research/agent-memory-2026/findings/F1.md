# F1: Rolling context windows and importance scoring for agent memory

## Findings

### [1] CrewAI uses a three-signal composite scoring formula for memory retrieval that blends semantic similarity (vector distance), recency (exponential decay), and LLM-inferred importance — with user-configurable weights.
- quote: "Recall results are ranked by a weighted combination of three signals: composite = semantic_weight * similarity + recency_weight * decay + importance_weight * importance"
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [2] CrewAI's unified Memory infers scope, categories, and importance automatically at save time via LLM analysis, enabling adaptive hierarchical organization without upfront schema design.
- quote: "When you call remember() without specifying a scope, the LLM analyzes the content and the existing scope tree, then suggests the best placement."
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [3] CrewAI's memory consolidation automatically handles deduplication at two thresholds: intra-batch dedup at 0.98 cosine similarity (within a single remember_many call, no LLM needed), and cross-record consolidation at 0.85 similarity (LLM decides keep/update/delete/insert_new).
- quote: "consolidation_threshold (default 0.85) -- Similarity above which consolidation is triggered on save. Set to 1.0 to disable."
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [4] CrewAI's default composite scoring weights are recency=0.3, semantic=0.5, importance=0.2, with a 30-day recency half-life; these are tunable per Memory instance to suit fast-moving vs. knowledge-base use cases.
- quote: "recency_weight=0.3, semantic_weight=0.5, importance_weight=0.2, recency_half_life_days=30"
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [5] CrewAI supports shallow recall (pure vector search, ~200ms, no LLM) and deep recall (multi-step LLM query analysis, scope selection, confidence-based routing, optional recursive exploration) — with a 200-character query threshold below which LLM analysis is skipped even in deep mode.
- quote: "Smart LLM skip: Queries shorter than query_analysis_threshold (default 200 characters) skip the LLM query analysis entirely, even in deep mode."
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [6] LangChain manages rolling context via three middleware-pattern strategies applied to the message list: trim messages (token-count-based truncation with keep-last strategy), delete messages (permanent removal of specific or all messages), and summarize messages (LLM compression via SummarizationMiddleware triggered at a token threshold).
- quote: "Common solutions are: Trim messages / Delete messages / Summarize messages"
- url: https://python.langchain.com/docs/modules/memory/how_to/
- source_type: primary
- published: unknown
- confidence: high

### [7] LangChain's SummarizationMiddleware triggers summarization when a token count threshold is reached (e.g., trigger=("tokens", 4000)) and retains a configurable number of recent messages (e.g., keep=("messages", 20)), using a separate (typically cheaper) model for the summarization step.
- quote: "SummarizationMiddleware(model="gpt-5.4-mini", trigger=("tokens", 4000), keep=("messages", 20))"
- url: https://python.langchain.com/docs/modules/memory/how_to/
- source_type: primary
- published: unknown
- confidence: high

### [8] LangChain's memory is state-based, managed through AgentState (message list) with checkpointers (InMemorySaver, PostgresSaver) persisting thread state, enabling thread resumption; short-term memory updates on each agent invocation or tool completion step.
- quote: "State is persisted to a database (or memory) using a checkpointer so the thread can be resumed at any time."
- url: https://python.langchain.com/docs/modules/memory/how_to/
- source_type: primary
- published: unknown
- confidence: high

### [9] CrewAI's memory runs saves in a non-blocking background thread via remember_many(), while recall() automatically calls drain_writes() before searching to ensure read consistency — preventing stale reads without explicit coordination.
- quote: "remember_many() is non-blocking -- it submits the encoding pipeline to a background thread and returns immediately."
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [10] CrewAI uses a hierarchical scope tree (e.g., /project/alpha, /agent/researcher) that provides context-dependent memory isolation and precision, with agents restricted to subtree views via MemoryScope, while slices allow cross-scope read access for multi-agent scenarios.
- quote: "Scopes provide context-dependent memory -- when you recall within a scope, you only search that branch of the tree, which improves both precision and performance."
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [11] CrewAI supports 12 embedder providers (OpenAI, Ollama, Azure, Google, Cohere, VoyageAI, AWS Bedrock, HuggingFace, Jina, IBM WatsonX, SentenceTransformer, Custom) and multiple LLM providers for memory analysis, enabling fully local/private deployments with Ollama.
- quote: "For fully offline/private operation, use a local model for both the LLM and embedder: memory = Memory(llm="ollama/llama3.2", embedder={\"provider\": \"ollama\", \"config\": {\"model_name\": \"mxbai-embed-large\"}})"
- url: https://docs.crewai.com/concepts/memory/
- source_type: primary
- published: unknown
- confidence: high

### [12] LangChain's trim_messages strategy preserves the first message (system prompt) and keeps a configurable number of most recent messages, using token-count estimation to decide when to trigger truncation before the LLM call.
- quote: "One way to decide when to truncate messages is to count the tokens in the message history and truncate whenever it approaches that limit."
- url: https://python.langchain.com/docs/modules/memory/how_to/
- source_type: primary
- published: unknown
- confidence: high
