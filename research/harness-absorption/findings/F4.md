# F4: Token overhead of extension system

## Findings

### [1] Pi's bare system prompt + tool schemas total under 1,000 tokens
- quote: "pi's system prompt and tool definitions together come in below 1000 tokens"
- url: https://mariozechner.at/posts/2025-11-30-pi-coding-agent/
- source_type: primary
- published: 2025-11-30
- confidence: high

### [2] Pi's minimal first-request overhead is 1,148 tokens vs OpenCode's 6,383 and Codex's 11,882
- quote: "Pi: 1,148 [total input tokens], OpenCode: 6,357, Codex: 11,882" for a fresh "Hi. Reply with exactly OK" prompt
- url: https://github.com/earendil-works/pi/discussions/6646
- source_type: primary
- published: 2025-07-14
- confidence: high

### [3] Pi uses 81% less total input and 55% less uncached input than OpenCode on MCP tasks
- quote: "Pi used 81.1% less total input; 55.5% less uncached input; 27.5% fewer generated tokens; 52.6% fewer model requests" in an MCP-heavy benchmark
- url: https://github.com/earendil-works/pi/discussions/6646
- source_type: primary
- published: 2025-07-14
- confidence: high

### [4] Pi MCP work unit cost was $0.199 vs OpenCode's $0.421 (52.8% less per unit)
- quote: "Pi cost 52.8% less per equivalent completed work unit. OpenCode cost 2.12 times as much." Using hypothetical pricing ($5/M uncached input, $0.50/M cache read, $30/M output)
- url: https://github.com/earendil-works/pi/discussions/6646
- source_type: primary
- published: 2025-07-14
- confidence: high

### [5] Extensions add zero overhead until their tools are actually called
- quote: "Skills: Capability packages with instructions and tools, loaded on-demand. Progressive disclosure without busting the prompt cache."
- url: https://pi.dev
- source_type: primary
- published: unknown
- confidence: high

### [6] Skills use progressive disclosure — loaded on-demand via /skill:name, not injected into every request
- quote: "Skills are available as /skill:name or let the agent load them automatically. Progressive disclosure without busting the prompt cache."
- url: https://github.com/earendil-works/pi/tree/main/packages/coding-agent#skills
- source_type: primary
- published: unknown
- confidence: high

### [7] Extensions can inject persistent messages via before_agent_start event — token cost is extension-controlled
- quote: "before_agent_start: Fired after user submits prompt, before agent loop. Can inject a message and/or modify the system prompt."
- url: https://pi.dev/docs/latest/extensions
- source_type: primary
- published: unknown
- confidence: high

### [8] Extension-registered custom tools add tool-schema tokens to each request; Pi has only 4 built-in tools vs OpenCode's larger stable prefix
- quote: "OpenCode begins with roughly 6.3K tokens of framework and tool schemas. Pi begins near 1.1–1.4K. OpenCode therefore has a large identical prefix to reuse on every request."
- url: https://github.com/earendil-works/pi/discussions/6646
- source_type: primary
- published: 2025-07-14
- confidence: high

### [9] The context event lets extensions prune messages before each LLM call — reducing token use rather than increasing it
- quote: "context: Fired before each LLM call. Modify messages non-destructively."
- url: https://pi.dev/docs/latest/extensions
- source_type: primary
- published: unknown
- confidence: high

### [10] Pi has intermittent cache-miss behavior; no deterministic cache-invalidation bug was found
- quote: "Pi sometimes had complete zero-cache requests inside an otherwise append-only persistent session. No deterministic context-rewrite or invalidation bug was demonstrated."
- url: https://github.com/earendil-works/pi/discussions/6646
- source_type: primary
- published: 2025-07-14
- confidence: medium

### [11] The pai-acp extension (model-driven context compression) addresses long-session token growth via LLM-controlled compression
- quote: "ACP intercepts Pi's context event... the LLM decides when and what to compress into high-fidelity summaries, preserving critical details while reclaiming context space."
- url: https://github.com/earendil-works/pi/discussions/7414
- source_type: community
- published: 2025-08-01
- confidence: medium

### [12] Extension API uses jiti loader with restricted surface — internal modules inaccessible to extensions
- quote: "pi's extension loader (jiti) aliases @earendil-works/pi-ai to dist/compat.js with an allowlist of only compat, oauth, and providers/all"
- url: https://github.com/earendil-works/pi/discussions/7474
- source_type: primary
- published: 2025-08-02
- confidence: high

## Dead ends
- pi.agent domain does not resolve (pi.dev is the canonical site)
- GitHub Discussions page requires login to read comments; key follow-up exchanges invisible
- No official benchmark report from pi maintainers on extension token overhead specifically
- No documentation of per-tool-schema token cost per extension tool registration
