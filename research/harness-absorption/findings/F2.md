# F2: OpenCode event system and observability

## Findings

### [1] OpenCode exposes a Server-Sent Events (SSE) stream at `GET /event` for real-time event subscription
- quote: "GET /event — Server-sent events stream. First event is server.connected, then bus events"
- url: https://opencode.ai/docs/server
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [2] The JS/TS SDK provides `client.event.subscribe()` which returns an async iterable SSE stream of all bus events
- quote: "event.subscribe() — Server-sent events stream. Response: Server-sent events stream. Example: for await (const event of events.stream) { console.log('Event:', event.type, event.properties) }"
- url: https://opencode.ai/docs/sdk
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [3] OpenCode plugins subscribe to named lifecycle events via hook functions, with 25+ distinct event types across 8 categories
- quote: "Plugins can subscribe to events as seen below... Command Events: command.executed; File Events: file.edited, file.watcher.updated; Installation Events: installation.updated; LSP Events: lsp.client.diagnostics, lsp.updated; Message Events: message.part.removed, message.part.updated, message.removed, message.updated; Permission Events: permission.asked, permission.replied; Server Events: server.connected; Session Events: session.created, session.compacted, session.deleted, session.diff, session.error, session.idle, session.status, session.updated; Todo Events: todo.updated; Shell Events: shell.env; Tool Events: tool.execute.after, tool.execute.before; TUI Events: tui.prompt.append, tui.command.execute, tui.toast.show"
- url: https://opencode.ai/docs/plugins
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [4] Plugins intercept tool execution via `tool.execute.before` and `tool.execute.after` hooks, enabling external monitoring of agent actions
- quote: "If input.tool === 'read' and output.args.filePath.includes('.env') { throw new Error('Do not read .env files') } — Plugins can use client.app.log() for structured logging. Levels: debug, info, warn, error."
- url: https://opencode.ai/docs/plugins
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [5] A structured logging API at `POST /log` accepts `{ service, level, message, extra? }` for observability integration
- quote: "POST /log — Write log entry. Body: { service, level, message, extra? }. Response: boolean"
- url: https://opencode.ai/docs/server
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [6] Session state is fully auditable: sessions can be listed, exported as JSON, diffed, summarized, and deleted via the REST API and CLI
- quote: "GET /session — List all sessions; DELETE /session/:id — Delete a session and all its data; GET /session/:id/diff — Get the diff for this session; POST /session/:id/summarize — Summarize the session; opencode export [sessionID] — Export session data as JSON; opencode session list — List all OpenCode sessions"
- url: https://opencode.ai/docs/server; https://opencode.ai/docs/cli
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [7] The experimental event system is gated behind `OPENCODE_EXPERIMENTAL_EVENT_SYSTEM` env var
- quote: "OPENCODE_EXPERIMENTAL_EVENT_SYSTEM — Enable experimental event system"
- url: https://opencode.ai/docs/cli
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [8] An `experimental.session.compacting` hook allows plugins to inject or replace the context-summary prompt during session compaction
- quote: "Customize the context included when a session is compacted — The experimental.session.compacting hook fires before the LLM generates a continuation summary. Use it to inject domain-specific context."
- url: https://opencode.ai/docs/plugins
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [9] Permission events (`permission.asked`, `permission.replied`) fire on every access-control decision, enabling audit trails of agent authorization decisions
- quote: "Permission Events: permission.asked, permission.replied"
- url: https://opencode.ai/docs/plugins
- source_type: primary
- published: Aug 6, 2026
- confidence: high

### [10] Session idle/error/status events track agent lifecycle state for external monitoring dashboards
- quote: "Session Events: session.created, session.compacted, session.deleted, session.diff, session.error, session.idle, session.status, session.updated"
- url: https://opencode.ai/docs/plugins
- source_type: primary
- published: Aug 6, 2026
- confidence: high

## Dead ends
- "eventStore" as a named concept does not appear in any public OpenCode documentation; OVAV's memory references it but the public docs describe the event system via SSE streams, plugin hooks, and REST endpoints without using that exact term.
- No documentation found for a dedicated audit-trail API with filtering/query capabilities; session audit is supported through full session export but not granular event queries.
- The `OPENCODE_EXPERIMENTAL_EVENT_SYSTEM` flag is referenced but its specific capabilities beyond the documented event system are not described in public docs.

## Suggested follow-ups
- Investigate what additional events or capabilities the experimental event system (`OPENCODE_EXPERIMENTAL_EVENT_SYSTEM`) enables beyond the documented plugin hook taxonomy.
- Determine whether the session database (exposed via `opencode db path`) stores a queryable event log vs. only session metadata, and what the schema looks like for external integration.
- Examine OVAV's own codebase (go-runtime/internal/ows/handlers.go) to confirm the eventStore concept and how OVAV binds to OpenCode's event bus.
