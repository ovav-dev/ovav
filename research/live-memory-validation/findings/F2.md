# F2: Proactive vs reactive memory injection

## Findings

### [1] All surveyed LLM agent memory frameworks use reactive (pull-based) retrieval; no proactive push system was found in the literature.

The dominant memory retrieval pattern in all major agent frameworks is R(M, c) — computing similarity between stored memory M and the upcoming context c — exactly as formalized in the 2024 survey "A Survey on the Memory Mechanism of Large Language Model based Agents" (arXiv:2404.13501). Memory reading is triggered by the current context, not injected before the model asks. This is true for Generative Agents (Park et al., 2023), MemGPT (Packer et al., arXiv:2310.08560), Reflexion (Shinn et al., arXiv:2303.11366), and MemoryBank. The Memory Mechanism Survey's future directions section (Aug 2024) identifies parametric memory, multi-agent memory, lifelong learning, and humanoid agents as open directions — with no mention of proactive injection.

- quote: "Memory Reading: This operation aims to obtain important information from the memory to support the next agent action. It corresponds to the third phase of the agent-environment interaction process… R is usually implemented by computing the similarity between M_t^k and c_{t+1}^k."
- url: https://arxiv.org/abs/2404.13501
- source_type: primary
- published: 2024-04-21
- confidence: high

### [2] CRAG (Corrective Retrieval Augmented Generation) uses a confidence-based retrieval evaluator that triggers different retrieval actions, but remains reactive (post-retrieval quality assessment).

CRAG (arXiv:2401.15884, Jan 2024) introduces a "retrieval evaluator" that assesses the overall quality of retrieved documents after retrieval occurs, and triggers knowledge refinement actions based on confidence. This is corrective but still reactive — it responds to retrieval quality, not to model struggle before a query. The evaluate-then-act pattern is the closest thing to proactive retrieval found, but it does not inject memory context before the model asks.

- quote: "A lightweight retrieval evaluator is designed to assess the overall quality of retrieved documents for a query, returning a confidence degree based on which different knowledge retrieval actions can be triggered."
- url: https://arxiv.org/abs/2401.15884
- source_type: primary
- published: 2024-01-29
- confidence: high

### [3] MemGPT uses OS-inspired hierarchical memory with paging and interrupts, but retrieval is still triggered reactively via context overflow and explicit function calls.

MemGPT (arXiv:2310.08560, Oct 2023) draws inspiration from OS memory management, using virtual context management with main context and archival storage. Memory is "pulled" via function calls (PostgreSQL vector similarity search) when the agent's context overflows or when the agent explicitly searches. The system uses "interrupts" to manage control flow, but these are event-driven (user message, scheduled), not triggered by detected model confusion.

- quote: "MemGPT queries archival storage via function calling, which pulls paginated search results into main context… events trigger LLM inference."
- url: https://arxiv.org/abs/2310.08560
- source_type: primary
- published: 2023-10-12
- confidence: high

### [4] Reflexion stores verbal reflections in an episodic memory buffer after feedback signals, then retrieves past reflections for subsequent trials — reactive to prior failures.

Reflexion (arXiv:2303.11366, Mar 2023) agents verbally reflect on task feedback signals after they occur, store reflective text in an episodic memory buffer, and retrieve from this buffer to induce better decision-making in subsequent trials. This is the standard reactive-on-failure pattern: store experience after outcome is known, retrieve on next similar task. The trigger for reflection is external feedback, not internal struggle detection.

- quote: "Reflexion agents verbally reflect on task feedback signals, then maintain their own reflective text in an episodic memory buffer to induce better decision-making in subsequent trials."
- url: https://arxiv.org/abs/2303.11366
- source_type: primary
- published: 2023-03-20
- confidence: high

### [5] Tree of Thoughts enables model self-evaluation of reasoning steps before proceeding, a form of metacognitive proactive reasoning — but not memory injection.

Tree of Thoughts (arXiv:2305.10601, May 2023, NeurIPS) allows the model to "consider multiple different reasoning paths and self-evaluate choices to decide the next course of action, as well as looking ahead or backtracking." This is proactive in the sense of deliberate evaluation before continuing, but it does not inject external memory context — it is purely intra-model reasoning state management.

- quote: "ToT allows LMs to perform deliberate decision making by considering multiple different reasoning paths and self-evaluating choices to decide the next course of action."
- url: https://arxiv.org/abs/2305.10601
- source_type: primary
- published: 2023-05-17
- confidence: high

### [6] No research was found on memory injection triggered by detected model confusion, uncertainty, or problem-similarity prediction before a query is formulated.

### [7] The Memory Mechanism Survey (2024) explicitly categorizes memory operations as write→manage→read, where "read" is defined as context-similarity retrieval, with no proactive injection operation defined.

The survey (arXiv:2404.13501) defines three memory operations: Memory Writing (projecting observations into stored memory), Memory Management (summarization, merging, forgetting), and Memory Reading (retrieval via R(M, c)). No "triggered injection" or "push" operation appears in the taxonomy. The field's terminology and framework do not yet include a proactive injection category.

- quote: "The agent memory module implements these phases through three operations including memory writing, memory management, and memory reading."
- url: https://arxiv.org/abs/2404.13501
- source_type: primary
- published: 2024-04-21
- confidence: high

### [9] CRAG's "decompose-then-recompose" algorithm for selective focus on key information is the most similar proactive signal processing found, but it operates on retrieved documents post-retrieval.

CRAG includes a decompose-then-recompose algorithm that "selectively focuses on key information and filters out irrelevant information" in retrieved documents. While this involves proactive content selection within the RAG pipeline, it does not constitute proactive memory injection before a query — it operates after retrieval is triggered.

- quote: "A decompose-then-recompose algorithm is designed for retrieved documents to selectively focus on key information and filter out irrelevant information in them."
- url: https://arxiv.org/abs/2401.15884
- source_type: primary
- published: 2024-01-29
- confidence: high
