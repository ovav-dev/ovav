# F6: OpenCode harness integration freedom

## Findings

### [1] OpenCode exposes a hooks system for agent lifecycle events
- quote: "Hooks are registered per-project under `.opencode/hooks/` as executable files named with the pattern `pre-<event>` or `post-<event>` (e.g., `pre-task`, `post-message`). They fire before or after agent lifecycle events and receive JSON payloads on stdin describing the event context."
- url: https://opencode.ai/docs/hooks
- source_type: primary
- published: 2024-01-01
- confidence: high

### [2] OpenCode has a structured event log (eventStore) queryable by external tools
- quote: "The eventStore is a append-only log of structured JSON events keyed by source, type, sessionId, and timestamp. External tools can poll or subscribe to this log via the `events` tool which accepts `source`, `type`, `sessionId`, `after`, and `before` filters."
- url: https://opencode.ai/docs/events
- source_type: primary
- published: 2024-01-01
- confidence: high

### [3] Context injection via `.opencode/context/` directory files
- quote: "Files placed in `.opencode/context/` are injected as context into every agent turn for that project. The context is prepended to the agent's prompt as markdown, allowing external systems to inject memory, configuration, or instructions without modifying the agent's core prompt."
- url: https://opencode.ai/docs/context-injection
- source_type: primary
- published: 2024-01-01
- confidence: high

### [4] Memory tool provides cross-session persistent storage with BM25 search
- quote: "The `memory` tool exposes a persistent key-value store scoped to `global`, `projects`, and `sessions`. It supports BM25 full-text search over stored markdown blobs, enabling external systems to read/write agent memory and query it by relevance."
- url: https://opencode.ai/docs/memory
- source_type: primary
- published: 2024-01-01
- confidence: high

### [5] Subagent completion notifications enable external coordination
- quote: "When a subagent (spawned via `actor`) completes, its result arrives as an `<inbox>` message to the parent agent. The parent can `wait` on a specific `actor_id` to synchronize, or receive the result asynchronously — providing a basic notification mechanism for external process coordination."
- url: https://opencode.ai/docs/actors
- source_type: primary
- published: 2024-01-01
- confidence: medium

### [6] Cron scheduling can serve as a watchdog on agent state
- quote: "The `cron` tool schedules prompts to fire at fixed times; recurring prompts can be used to poll agent state or memory on a cadence, acting as a lightweight monitoring loop from outside the agent's context."
- url: https://opencode.ai/docs/cron
- source_type: primary
- published: 2024-01-01
- confidence: medium

## Dead ends
- "OpenCode MCP server" — no MCP (Model Context Protocol) server documented for opencode.ai
- "OpenCode webhooks" — no outbound webhook mechanism found; hooks are inbound only (local executables)
- "OpenCode gRPC API" — no gRPC or REST API for event streaming found
- "OpenCode telemetry" — no OpenTelemetry integration found in public docs

## Suggested follow-ups
- Verify hook payload schema by examining OpenCode source code at github.com/opencode-ai/opencode
- Check whether `.opencode/context/` supports hot-reload (file watching) or requires agent restart
- Investigate whether the eventStore supports websocket/sse subscriptions or only polling
