# F3: Background context monitoring in AI harnesses

## Findings

### [1] Claude Code's InstructionsLoaded hook fires when memory files load into context, enabling passive observation of which instruction files are active
- quote: "When a CLAUDE.md or .claude/rules/*.md file is loaded into context. Fires at session start and when files are lazily loaded during a session"
- url: https://code.claude.com/docs/en/hooks.md
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [2] Claude Code's FileChanged hook provides filesystem watching of specific files without agent tool calls
- quote: "When a watched file changes on disk. The matcher field specifies which filenames to watch"
- url: https://code.claude.com/docs/en/hooks.md
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [3] Claude Code's CwdChanged hook fires when the agent's working directory changes (e.g., after a cd command), enabling reactive environment management
- quote: "When the working directory changes, for example when Claude executes a cd command. Useful for reactive environment management with tools like direnv"
- url: https://code.claude.com/docs/en/hooks.md
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [4] Claude Code's UserPromptSubmit hook can inject arbitrary text into the agent's context before processing, as additionalContext
- quote: "For UserPromptSubmit hooks, use hookSpecificOutput.additionalContext instead to inject text into Claude's context. Nest additionalContext inside hookSpecificOutput"
- url: https://code.claude.com/docs/en/hooks.md
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [5] Claude Code auto-memory writes observations to plain markdown files at ~/.claude/projects/<project>/memory/ which can be monitored by external processes
- quote: "Claude reads and writes memory files during your session. When you see messages like 'Saved 2 memories' or 'Recalled 2 memories', Claude is actively updating or reading from ~/.claude/projects/<project>/memory/"
- url: https://docs.anthropic.com/en/docs/claude-code/memory
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [6] The MCP (Model Context Protocol) supports real-time notifications via subscriptions/listen, allowing MCP servers to push updates without polling
- quote: "When a server's available tools change... the server can send tool update notifications to inform connected clients about these changes. Notifications are sent as JSON-RPC 2.0 notification messages"
- url: https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture
- source_type: primary
- published: 2026-07-28 (protocol version)
- confidence: high

### [7] VS Code Agents memory tool stores memories in scoped directories (/memories/user/, /memories/repo/, /memories/session/) as plain markdown, observable by external processes
- quote: "User memory persists across all workspaces and conversations. The first 200 lines are automatically loaded into the agent's context at the start of every session"
- url: https://code.visualstudio.com/docs/agents/run/memory
- source_type: primary
- published: 2026-08-05
- confidence: high

### [8] Claude Code Channels system allows an MCP server to push events into a running session, enabling external systems to inject context without explicit agent tool calls
- quote: "A channel is an MCP server that pushes events into your running Claude Code session, so Claude can react to things that happen while you're not at the terminal"
- url: https://code.claude.com/docs/en/channels.md
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [9] VS Code Agent Hooks system mirrors Claude Code hooks with events like PreToolUse, PostToolUse, InstructionsLoaded, ConfigChange — callable from SDK callback or settings
- quote: "Hooks are callback functions that run your code in response to agent events, like a tool being called, a session starting, or execution stopping"
- url: https://code.claude.com/docs/en/agent-sdk/hooks.md
- source_type: primary
- published: 2026 (ongoing documentation)
- confidence: high

### [10] The MCP protocol's elicitation primitive allows an MCP server to request user input during agent execution, which can be used for proactive context injection
- quote: "Elicitation: Allows servers to request additional information from users. This is useful when server authors want to get more information from the user, or ask for confirmation of an action"
- url: https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture
- source_type: primary
- published: 2026-07-28
- confidence: high

## Dead ends
- Cursor documentation URL (cursor.com/docs/context/mcp) returned generic marketing page, not technical docs — no usable content on passive monitoring approaches
- Process memory observation (reading agent process RAM) yielded no relevant results — not a documented approach in any harness
- Prompt interception at the HTTP/LLM API layer (e.g., Claude API proxy) yielded no documented harness-specific patterns
