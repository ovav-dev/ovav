## 6. Lessons learned (operational)

1. **Side-channel injection risk**: ad-hoc scripts touching `permission_authority.json` directly is the highest-risk consumer pattern. The Consumer Bridge's `grant` CEO-gated patch + registry single-source-of-truth eliminates this class of attack.

2. **Filesystem-only code disappears**: Braka's advanced OWS code never made it to git. Cleanup wiped it. Lesson: any non-trivial automation must be committed or documented as artifacts even before "shipping".

3. **CEO waiver semantics**: `protected_branch_waiver.yaml` file presence indicates active gate, but actual lifetime is governed by `duration_minutes`. The `check-protected` command returns 0 if the gate is open. Protect the gate by NOT extending waivers without explicit CEO action.

4. **Tier gating prevents over-privilege**: `business` tier commands (owa, owr) cannot be invoked by `free` tier consumers. This protects free users from accidentally triggering expensive cleanup operations.

5. **Best-practice 2026 for worktrees**: sibling pattern over in-repo. Reduces git status noise, simplifies `.gitignore`, matches jj/git-butler norms.
