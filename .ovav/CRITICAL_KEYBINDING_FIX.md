## 🚨 Problema Crítico Identificado

Después del reinicio, las teclas modificadoras no funcionaban correctamente en WezTerm + WSL2:

- ❌ **Shift+Enter**: Enviaba comando en lugar de nueva línea
- ❌ **Ctrl+B**: Borraba caracteres en lugar de mover cursor
- ✅ **Ctrl+Shift+Enter**: Funcionaba (confirmaba que era problema de modifiers)

---

## 🔍 Root Cause

**WezTerm en Windows + WSL2** tiene un bug conocido con el manejo de teclas modificadoras. El puente entre Windows host y WSL2 guest no transmite correctamente los eventos de teclado con modificadores simples (Shift solo), pero sí funciona con combinaciones complejas (Ctrl+Shift).

---

## ✅ Fix Aplicado

### **Archivo:** `~/.wezterm.lua`

```lua
-- FIX: Windows WSL2 key modifier handling
config.send_composed_key_when_left_alt_pressed = false
config.send_composed_key_when_right_alt_pressed = false
config.use_ime = false
config.dead_key_timeout_ms = 0
```

### **Explicación:**

1. **`send_composed_key_when_*_alt_pressed = false`**
   - Previene que WezTerm envíe caracteres compuestos cuando Alt está presionado
   - Evita conflictos con keybindings que usan Alt

2. **`use_ime = false`**
   - Deshabilita Input Method Editor (IME)
   - IME puede interceptar y modificar eventos de teclado
   - Causa problemas con Shift y otras teclas modificadoras

3. **`dead_key_timeout_ms = 0`**
   - Deshabilita dead keys completamente
   - Dead keys esperan una segunda tecla para crear caracteres especiales
   - Esto causaba delays y comportamientos inesperados con Shift
