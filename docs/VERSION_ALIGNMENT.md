## Taxonomía de Versiones OVAV

OVAV tiene **4 tipos de versión** que no deben confundirse:

| Tipo | Ámbito | Ejemplo actual | Archivo fuente |
|------|--------|----------------|----------------|
| **System Version** | Todo el sistema técnico (Go runtime + web) | `3.4.0` | `VERSION` (root) |
| **Go Runtime Version** | Subsistema Go compilado + binary | `3.4.0` | `go-runtime/VERSION` + `shared.go` |
| **pi-memory Version** | Motor de memoria vectorial npm | `3.4.0` | `ovav-systems/pi-memory/VERSION` |
| **Product Version** | Producto comercial user-facing | `2.3.2` | `caps.yaml product.version` |

> **Regla de oro:** `System Version` es la versión padre. Las demás la siguen o son submúltiplos coherentes. `Product Version` es independiente — es lo que se entrega al cliente.

## Cómo Bumpear Correctamente

Cuando se hace bump de versión del sistema:

```bash
# 1. System version (root)
echo "3.4.0" > VERSION

# 2. Go runtime version
echo "3.4.0" > go-runtime/VERSION

# 3. pi-memory version
echo "3.4.0" > ovav-systems/pi-memory/VERSION

# 4. git commit
git add VERSION go-runtime/VERSION ovav-systems/pi-memory/VERSION
git commit -m "chore: bump system version to X.Y.Z"
```

## Producto Comercial vs Sistema Técnico

- **Producto comercial (`caps.yaml product.version`):** `2.3.2` — Este es el número que ve el cliente. Solo se bumppea en releases formales vía PR a `main`.
- **Sistema técnico (`VERSION`):** `3.4.0` — tracks la evolución interna del motor. No se sincroniza con el producto comercial.

这两个 son independentes y cada uno tiene su cadence.
