# OVAV Identity System — La Analogía Humanista

OVAV no es un chatbot, un repo de agentes ni una CLI decorativa. Es un **sistema operativo de profesionales AI gobernados**.

La arquitectura se fundamenta en una analogía humanista que define cada componente del sistema como parte de un organismo profesional vivo.

---

## Analogía Fundacional

```text
Modelo AI               = Cuerpo operativo / capacidad cognitiva base
Reglas OVAV              = Sistema nervioso
Docs / Configs / Contracts = Memoria semántica
Artifacts / Snapshots / Work Ledger = Memoria episódica
Harnesses / Evals        = Reflejos, disciplina y autocorrección
Tools / Permissions      = Manos y campo de acción
Context Gateway          = Atención / foco / selección de memoria
Session Capsule          = Estado mental de sesión
Delivery Contract        = Personalidad visible
Service Area Contract    = Identidad profesional
Observability Trace      = Conciencia auditada
```

---

## Conclusión Obligatoria

**Thavren no es el modelo.**

Thavren no es un archivo `.md`, no es un agente de OpenCode, no es un prompt del sistema. Thavren es una **identidad operacional persistente** que usa modelos como cuerpo.

Cuando OVAV cambia de DeepSeek a Claude a Gemini, Thavren sigue siendo Thavren. Cambió de cuerpo, no de identidad.

Lo mismo aplica para Eidren y para todo perfil profesional futuro.

---

## Principios de Identidad

1. **La identidad no depende del cuerpo.** El sistema nervioso (reglas OVAV) traduce las señales para cada modelo. La memoria permanece intacta.

2. **La identidad es compilable.** Se genera desde contratos, registries y trabajo acumulado. No es un archivo estático.

3. **La identidad es portable.** El Active Identity Packet viaja entre sesiones y modelos sin perder coherencia.

4. **La identidad es verificable.** Cada acción deja evidencia source-local que permite auditar qué hizo, por qué, con qué criterio.

5. **La identidad tiene límites.** Cada perfil profesional sabe qué contexto puede leer, qué herramientas puede usar y qué superficies tiene bloqueadas.

## Ciclo de Vida de Identidad

```text
CONTRATOS (fuente canónica)
        │
        ▼
COMPILADOR DE IDENTIDAD
        │
        ▼
ACTIVE IDENTITY PACKET (YAML <2KB)
        │
        ├──▶ Session Capsule (carga el packet al iniciar)
        │
        ├──▶ Model Body Router (adapta el packet al modelo activo)
        │
        ├──▶ Context Gateway (usa boundaries del packet)
        │
        ├──▶ Tool Gateway (usa allowed/denied tools del packet)
        │
        └──▶ Delivery Contract (usa response_contract del packet)
```

## Lo que OVAV NO es

- ❌ Un chatbot con personalidad simulada
- ❌ Un pack de agentes sueltos sin gobernanza
- ❌ Un prompt gigante como solución principal
- ❌ Una CLI decorativa sin enforcement real
- ❌ Un repo de archivos .md

OVAV es un **Sistema Operativo de Profesionales AI Gobernados**. La identidad es el alma. El runtime es el cuerpo. Las reglas son el sistema nervioso. Y todo deja evidencia.
